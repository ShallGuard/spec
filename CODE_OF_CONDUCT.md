# Code of Conduct

This page states how people treat each other in the ShallGuard project. It
applies to every repository of the [ShallGuard organization](https://github.com/shallguard).

## Our commitment

ShallGuard welcomes contributors of all backgrounds and all levels of
experience. The project is a respectful, constructive community without
harassment. Disagreement is normal. Hostility, discrimination,
intimidation, and personal attacks are not.

## Expected conduct

A contributor must:

- Discuss ideas, evidence, and code without an attack on a person.
- Give specific, useful, and respectful feedback.
- Read English from a non-native writer with good will, and help to improve
  it without a put-down of the author.
- State assumptions and limits honestly.
- Respect privacy, licensing, authorship, and confidential information.
- Take responsibility for each contribution, including content from a
  coding agent or from another generative tool.
- Correct a mistake or a wrong claim when someone finds it.

Harassment, discriminatory language, threats, continued disruption,
deliberate misrepresentation, and publication of the private information of
another person are not acceptable.

## Language and editorial contributions

A note from the maintainer: English is not my native language, and I
started to learn it later in life. I do not always have a natural feel for
idiomatic English. For this reason, a large language model helped to draft,
reword, or correct much of the prose of the project.

Help with grammar, clarity, tone, and wording is welcome. An editorial pull
request is a valued contribution. When a text reads unusual, blunt, or
ambiguous, assume good intent and ask.

An editorial change to a requirement statement must keep its technical
meaning. If a new wording can change the meaning of a requirement, treat
the change as a specification change. Discuss it and review it as such, not
as a grammar correction.

## Scope

This Code of Conduct applies to discussions in a repository, issues, pull
requests, reviews, project communication, and public interactions that
represent the project.

## Enforcement

A maintainer can remove, edit, or reject a contribution or a comment that
violates this Code of Conduct. The response depends on the severity and on
repetition. It can be a private correction, a warning, a temporary
restriction, or a permanent exclusion from the project spaces.

Send a report in private to the maintainer at `tomas.siegl@gmail.com`. The
maintainer handles a report as confidentially and as fairly as possible. If
a report concerns the current maintainer, use the private abuse report of
the hosting platform.
